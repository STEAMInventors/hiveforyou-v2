# Principles

## Pipeline (V2 experience)

Upload → Engine 1 discover → missingness & questions → user answers (versioned) → canonical study context → Engine 2 deep analysis → model proposes → code validates → persist Case Intelligence → Customer UX → Pro (paid/locked) UX.

Reprocess only when material evidence or context changes, or an explicitly defined analysis is required — not on reopen, view change, timeline, graph node, provenance drill-down, or Pro unlock alone.

## Laws

See foundational laws in [INDEX.md](../INDEX.md). In short:

- **Engine 1:** Model proposes. Pack defines. Code validates. Professional decides.
- **Engine 2:** Evidence provides reality. Model studies and proposes. Code validates structure and provenance. Canonical truth drives both views.
- **No chip → no claim.** **No validated claim → no factual representation.**
- Domain rules in **Domain Packs** only.
- One canonical truth for Customer and Pro.
- **Persist intelligence** instead of regenerating on every interaction.
- Evidence = truth; user intent = emphasis (never contaminates source truth).
- Q&A and processing runs are versioned and auditable.
